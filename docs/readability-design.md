# 可读性调整（2026-11-16）

## 问题与方向

原界面大量使用小于 12px 的文字和浅灰绿色前景，正文、辅助信息、选中状态之间区分不足。调整为中性浅灰页面、白色内容区、深色正文；绿色保留给主要操作、选中和成功状态。

## 统一规则

- 主正文 `#1d2939`，次级说明 `#475467`，辅助文字 `#5d687a`。
- 页面 `#f5f6f8`，内容区 `#ffffff`，弱背景 `#f3f5f7`，边框 `#d6dde5`。
- 操作绿 `#216348`，选中背景 `#e8f3ed`；状态同时保留文字及图标。
- 聊天、文档阅读和语义检索原文为 16px；数据表正文 14px；字段名、辅助说明至少 12px。
- 增强标题字重与行间距；数据页标题改为直接的「数据库查询」。
- 使用现有本机中文无衬线字体，取消功能页面中的细衬线小字。
- 手机端输入文字 16px，主要图标按钮、发送和开关提供 44px 操作区域；表格横向滚动限制在表格内部。

颜色变量与跨页面规则集中在 `frontend/src/theme.css`；原组件样式同步改用变量，并清理过小字号。主题在基础布局样式之后加载。

## 验证

前端 TypeScript 检查和生产构建通过。实际浏览器检查了数据表、聊天正文、文档列表、全文预览和设置窗口；桌面 1600×1000，手机 390×844 及 375×812。

使用计算后的文字颜色与实际背景逐层合成进行普通文字对比度抽查（不计禁用控件、背景被遮罩遮挡的区域及图标）：

| 场景 | 检查文字元素 | 最低对比度 | 低于要求的文字 |
| --- | --- | --- | --- |
| 数据表（含导航与字段名） | 234 | 4.96:1 | 0 |
| 聊天正文 | 66 | 5.21:1 | 0 |
| 设置窗口 | 15 | 5.64:1 | 0 |
| 手机全文阅读 | 14 | 7.03:1 | 0 |
| 375px 数据查询 | 102 | 4.96:1 | 0 |

这些检查针对已打开的实际页面状态，不等于完整 WCAG 审计。没有发现页面级横向溢出，文档和数据操作保持可用。截图保存在本机 `output/playwright/readability-*.png`。
